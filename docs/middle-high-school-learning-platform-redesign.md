## 0. 本次重构的最终结论

### 0.1 页面方向

初中和高中统一使用“星宝 AI 学习中心”这一套 PC 学习壳层。左上角始终提供小学、初中、高中三段式切换：

```text
小学 -> 现有地图/绘本/战斗体验
初中 -> 学习路径、课程、练习、个人画像
高中 -> 学习路径、课程、练习、个人画像；综合项目从课程卡和学习路径进入
```

初中和高中不再把地下实验室地图或研究站表单作为日常首页。初中地图不再作为用户入口；历史 `/middle-map` 路由只做兼容重定向到初中学习路径。高中综合项目改造成课程路径中的项目工作区，不增加第五个侧栏项。日常学习从 `/learn` 开始，所有课程、练习、实验、项目和进度共享同一份学习状态。

### 0.2 第一轮视觉取舍

第一轮只实现清晰、稳定的工作型页面：固定顶栏、固定侧栏、课程卡、练习区和三栏实验室。整体使用中性背景、高对比文字、少量状态色和不超过 6px 的圆角，优先保证 PC 端 1440x900 与 1920x1080 的可读性和操作效率。

第二轮再替换为主页一致的像素主题：像素星宝、像素课程图标、像素边框、阶段背景和小型状态动效。像素素材只能增强品牌和反馈，不能替代正文、代码、指标和无障碍文字。

### 0.3 课程与 AI 导师的关系

课程内容按《人工智能通识课》的能力链路组织为“概念 -> 编程 -> 数据 -> 模型 -> 生成式 AI -> 安全与项目”。在拿到比赛方正式课纲前，本文档中的课程 ID 和内容是可实施的首版蓝图，必须保留稳定 ID，后续只做官方条目映射和补充。

AI 导师是课程内的一种教学模式，不是独立的第五个侧栏页面。学生可以选择：

- 自主学习：阅读讲解、看示范、做练习和实验。
- AI 导师学习：星宝按当前课程讲解、流式出字幕、播放语音、展示幻灯片并在关键节点提问。
- 编程/实验：在固定模板中直接写 Python，运行后查看测试、输出和指标，再向星宝询问解释。

Dify 只负责适龄讲解、追问、受限的幻灯片文案和语音讲稿、实验结果解释以及项目答辩提问；判分、测试、指标、掌握度、解锁和项目通过条件始终由网页程序确定。

### 0.4 当前代码与本设计的关系

当前工作树已经包含统一学习壳层、初高中课程目录、`Unit -> Lesson -> Activity` 课程结构、确定性练习、Python 实验、个人画像、AI 导师本地 Mock、高中项目工作台，以及初中地图的兼容重定向。后续 AI 编程工具应优先补齐内容完整度、路由兼容、浏览器验收和 Dify 协议交接，不得为了换视觉而重写这些底层能力。

## 1. 文档目标

本文档重新定义小学阶段之后的初中、高中网页产品。新的产品不再以“地下实验室地图”和“高中研究站单页”作为主要学习界面，而是形成一个统一的 AI 学习平台：

```text
小学：保留现有地图、绘本、战斗和像素冒险体验
  -> 初中：统一学习中心，完成概念、练习、编程和模型实验
  -> 高中：沿用同一学习中心，增加数据、模型训练、审计和项目答辩
```

### 1.1 课程依据与确认边界

本文件中的课程主题依据 K12 人工智能通识的常见能力链路编排：理解 AI 与数据、学习基础编程、观察模型训练与评价、理解生成式 AI、形成安全与伦理意识，再进入高中阶段的数据、机器学习、模型审计与项目实践。

当前工作区未包含比赛方正式发布的《人工智能通识课》课程标准、知识点编码或必修课时表。因此 M-01 至 M-07、独立的 `middle-data-bias` 主题课，以及 H-01 至 H-09，是可实施的首版课程蓝图，不应表述为已经逐条等同官方教材。拿到官方附件后，应执行一次“官方条目 -> 课程章节 -> 练习/实验 -> 验收证据”的映射审查；缺失条目补入课程，冲突条目以官方要求为准，同时保留稳定的课程 ID 和历史学习数据迁移。

截图中的 DataCamp 页面只作为信息架构和交互节奏参考，不复制其品牌、配色、图形资产或具体页面。第一轮先建立简约、清晰、可用的 PC 布局；后续再把边框、图标、背景、角色和微动效逐步替换成与项目首页一致的像素主题。

## 2. 重构结论

### 2.1 建议重构

当前初高中功能已经具备课程数据、学习路径、练习、Python 实验、进度和高中项目存储，但页面表现存在三个问题：

1. 地图、课程、实验、进度和项目分散在不同页面，学生不容易理解“现在学什么、下一步做什么”。
2. 高中项目页一次展示大量文本框，更像后台录入表，不像教学过程。
3. 历史初中地图即使视觉体验较强，也不再承担课程导航、热点交互或编程工作。

因此需要重构页面组织方式，但不应推倒已经完成的底层能力。重构对象是导航、工作流和呈现层，不是重写课程存储、实验运行器或确定性评价器。

### 2.2 必须保留的现有能力

- 小学 `/map`、绘本、战斗、云朵转场和阶段完成结果。
- 初中地下实验室背景及 SVG 热点，可改为阶段开场和主题探索入口。
- `curriculum.ts` 中已经存在的课程事实和稳定课程 ID。
- `learning-paths.ts` 的先修关系、解锁纯函数和活动 ID。
- `learning-store.ts` 的学习状态、迁移、清洗和容量限制。
- `features/quiz` 的确定性练习判分和知识点证据。
- `features/lab` 的 Monaco、Pyodide、停止、超时、测试和结构化实验证据。
- `features/progress` 的掌握度、误区、复习推荐和阶段完成条件。
- `features/projects` 的结构化项目数据、确定性评价和报告导出。

### 2.3 调整或降级的现有页面

| 当前页面 | 新定位 | 迁移要求 |
|---|---|---|
| `/middle-map` | 历史初中地图兼容入口 | 保留旧链接可访问性，统一重定向到 `/learn?stage=middle_school&view=path`；不新增热点功能 |
| `/workspace` | 旧课程工作区 | 重构为统一课程工作区，保留旧查询参数兼容 |
| `/lab` | 独立 Python 实验页 | 嵌入统一学习壳层，保留现有运行协议和直达 URL |
| `/progress` | 独立进度页 | 内容迁移到“个人画像”，旧路由继续可访问或重定向 |
| `/high` | 高中研究站 | 改为统一学习中心的高中默认视图，保留解锁条件 |
| `/high/project/capstone` | 九字段项目表单 | 重构为分阶段项目工作台，继续复用原项目 schema 和存储 |

## 3. 产品目标与设计原则

### 3.1 核心目标

1. 学生进入平台后 10 秒内看懂当前学段、正在学习的课程和下一步任务。
2. 初中和高中使用同一套信息架构，难度通过课程、活动、提示和证据要求逐步提高。
3. 课程讲解、练习、编程、模型实验、AI 导师和个人进度在同一个平台内连贯切换。
4. 每次答题、代码运行和实验都形成确定性学习证据。
5. Dify 智能体提供适龄教学，不决定答案、分数、实验指标和课程解锁。
6. 即使 Dify、TTS 或网络不可用，固定课程、练习和编程实验仍可继续。

### 3.2 设计原则

- **任务优先**：首屏首先展示继续学习和当前任务，不制作营销英雄区。
- **少而清晰**：主侧边栏只保留学习路径、课程、练习、个人画像四项。
- **渐进展示**：项目和课程一次只显示当前步骤，不一次铺开所有表单。
- **确定性在前**：分数、解锁、代码测试和指标来自程序；AI 只解释。
- **适龄而不幼稚**：初中有像素角色和任务感，高中减少装饰但保持同一世界观。
- **PC 工作界面**：优先保证 1440x900 与 1920x1080 的信息密度、代码可读性和稳定布局。
- **像素主题克制使用**：像素风用于品牌、状态、角色和小型装饰，不使用低可读性的像素字体承载正文。
- **不做卡片套卡片**：课程卡可以成组出现，页面区块、工具区和工作台保持扁平。

## 4. 用户与关键任务

### 4.1 初中学生

- 理解 AI、数据、样本、特征、标签和模型预测。
- 完成短讲解、客观练习和代码追踪。
- 在引导下修改 Python、改变一个变量、观察结果并写出因果解释。
- 训练或模拟一个小型分类模型，理解错误、不确定性和数据偏差。
- 使用 AI 导师获得分级提示，而不是直接得到答案。

### 4.2 高中学生

- 使用 Python 处理固定数据，构建可复现实验。
- 区分训练、验证和测试，选择适合的指标。
- 观察损失、梯度下降、过拟合和模型审计。
- 完成结构化 AI 项目、模型卡、报告和答辩。
- 要求 AI 导师基于代码测试和实验数据追问证据。

### 4.3 教师或比赛演示人员

- 快速切换学段并展示不同年龄适配。
- 查看学生学习路径、掌握度、错误类型、实验记录和项目成果。
- 验证 AI 导师不是自由聊天，而是围绕课程、知识点和证据教学。
- 在 AI 不可用时展示固定课程和本地降级闭环。

### 4.4 功能分类与优先级

| 功能域 | P0 首版必须可用 | P1 完整教学闭环 | P2 后续增强 |
|---|---|---|---|
| 学段与导航 | 小学/初中/高中切换；四项侧栏；旧路由兼容 | 最近学习、搜索、快捷键和深链恢复 | 教师视角的班级筛选 |
| 课程内容 | manifest、路径、课程卡、Unit/Lesson/Activity | 资料引用、章节总结、课程结业挑战 | 教师 CMS 和正式课纲编辑 |
| 练习 | 单题模式、代码追踪、键盘 `1-4`、确定性判分 | 错题补救、间隔复习、每日任务 | 题库批量生产和教师自定义题 |
| 编程/实验 | Pyodide、模板、运行/停止/重置、固定测试 | 变量控制、指标、可复现实验和 Evidence | 更丰富的可视化和硬件接力 |
| AI 导师 | 本地 Mock、流式字幕、固定幻灯片、text-only 降级 | Dify BFF、PPT 逐页生成、语音队列、互动检查点 | 受控 TTS、跨设备同步 |
| 个人画像 | 掌握度、误区、证据次数、复习入口 | 作品、报告、推荐原因和数据导出/清除 | 教师授权的匿名汇总 |
| 高中项目 | 分步骤表单、实验引用、模型卡、确定性完成 | 报告复现信息、答辩问答和表达反馈 | 作品展和教师评审流程 |
| 安全与运维 | 未成年人数据最小化、沙箱、白名单、限流 | trace、版本、降级、迁移和离线恢复 | 正式账号、同步、备份和监护人权限 |

P0 功能必须在 Dify、TTS 或网络不可用时仍可演示；P1 在相应课程或项目任务启动前完成；P2 不得阻塞初高中首轮上线。

## 5. 统一信息架构

### 5.1 全局入口

建议新增统一入口：

```text
/learn?stage=middle_school&view=path
/learn?stage=middle_school&view=courses
/learn?stage=middle_school&view=practice
/learn?stage=middle_school&view=profile
/learn?stage=high_school&view=path
```

小学阶段仍进入现有小学主流程：

```text
选择“小学” -> /map
选择“初中” -> /learn?stage=middle_school&view=path
选择“高中” -> /learn?stage=high_school&view=path
```

阶段切换必须是明确的用户操作。切换后记录当前学段，但不能自动清除或覆盖其他学段进度。

### 5.2 主导航

左侧固定导航只有四项：

| 导航 | 目的 | 默认内容 |
|---|---|---|
| 学习路径 | 告诉学生先学什么、当前在哪、下一步是什么 | 章节路径、先修状态、继续学习 |
| 课程 | 浏览当前学段所有课程 | 课程筛选、课程卡、课程详情 |
| 练习 | 独立练习和错题补救 | 每日练习、专题练习、编程挑战、错题 |
| 个人画像 | 查看真实学习证据 | 掌握度、误区、实验、作品、推荐 |

“AI 导师”不作为第五个并列资料页，而是全局可启动的学习模式：

- 课程卡提供“AI 导师学习”。
- 课程详情提供“开启 AI 导师”。
- 编程实验提供“询问星宝”，进入课程限定的实验教练。
- 页面右下角可保留一个像素星宝按钮，但不能遮挡主要内容。

### 5.3 主要路由

| 路由 | 页面职责 |
|---|---|
| `/learn` | 统一学习大厅，按 `stage` 与 `view` 渲染 |
| `/learn/course/[courseId]` | 课程详情和章节目录 |
| `/learn/lesson/[lessonId]` | 自主学习工作区 |
| `/learn/tutor/[lessonId]` | AI 导师授课模式 |
| `/learn/practice/[practiceSetId]` | 客观题、代码追踪和结果解释 |
| `/lab` | Python 编程和模型实验，嵌入统一壳层 |
| `/learn/project/[projectId]` | 分阶段项目工作台 |
| `/middle-map` | 历史初中地图兼容重定向 |
| `/map` | 现有小学地图 |

旧路由不得突然失效。`/workspace?course=...`、`/progress?...` 和 `/high/project/...` 在迁移期间继续工作，并逐步指向新的页面组件。

### 5.4 路由解析与跨学段守卫

所有深链先经过一个纯函数 resolver，再渲染页面。resolver 同时校验 `stage`、`view`、`courseId`、`lessonId`、`activityId`、`template`、`mode` 和 `projectId`，不能让页面分别校验“全局合法”参数后拼出跨学段组合。

```ts
type LearningRouteInput = {
  stage: "middle_school" | "high_school";
  view?: "path" | "courses" | "practice" | "profile";
  courseId?: string;
  lessonId?: string;
  activityId?: string;
  templateId?: string;
  mode?: "guided" | "independent" | "research" | "project";
  projectId?: string;
};

type LearningRouteResult =
  | { kind: "ready"; canonicalPath: string; stage: LearningRouteInput["stage"] }
  | { kind: "locked"; canonicalPath: string; missingEvidenceIds: string[] }
  | { kind: "redirect"; canonicalPath: string; reason: "legacy" | "invalid" | "cross_stage" };
```

固定兼容关系：`/high` -> `/learn?stage=high_school&view=path`；`/high/project/:id` -> `/learn/project/:id`；`/workspace?course=...` 保留查询参数并进入对应 Lesson；`/progress` -> `/learn?view=profile`；`/lab` 必须按 `stage + templateId + mode` 白名单解析。未知 ID、非法 mode、跨学段模板和缺失项目统一进入安全重定向或 404，不允许渲染“看起来正确但实际没有完成条件”的页面。

resolver 必须有矩阵测试覆盖：每个初中/高中模板的合法组合、跨学段组合、锁定活动、直接深链、刷新恢复和旧路由跳转。`H-09` 的 `high-capstone-project` 作为 `project-only` manifest 注册，不能被普通课程卡重复统计为已完成课程。

## 13. AI 导师授课模式

### 13.1 页面目标

AI 导师不是普通聊天窗口，而是一段可暂停、可提问、带幻灯片和语音同步的教学会话。

### 13.2 页面布局

参考用户提供的分屏截图：

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 返回课程  课程/章节名称             声音/速度/字幕               退出     │
├───────────────────────┬──────────────────────────────────────┬───────────┤
│ AI 导师讲解与提问      │ 当前幻灯片/演示/代码                  │ 进度       │
│ 流式字幕               │ 16:9 稳定画布                        │ 笔记       │
│ 学生回答区域           │ 不随字幕长度改变尺寸                  │ 提问       │
│ 34%                   │ 58%                                  │ 8%         │
└───────────────────────┴──────────────────────────────────────┴───────────┘
```

### 13.3 交互要求

- 开始前显示本节目标、预计时间和教学模式。
- AI 先生成课程提纲和前两页幻灯片，再开始语音，避免长时间空白。
- 字幕按句流式显示，语音以完整句为单位排队播放。
- 幻灯片切换必须与对应语音段落绑定。
- 学生可以暂停、继续、上一页、下一页、调速、开关字幕和重复当前段落。
- AI 每 2-4 页安排一次预测、选择、口头回答或代码观察，不允许连续十分钟单向朗读。
- 学生提问后暂停主讲，回答结束再回到原教学位置。
- 会话结束生成课程总结、掌握证据和下一步，不让 AI 自己给最终分数。

### 13.4 教学状态机

```text
idle
  -> planning
  -> prebuffering
  -> presenting
  -> awaiting_interaction
  -> presenting
  -> summarizing
  -> completed

任意生成节点失败 -> degraded_static_lesson
语音失败 -> text_only
用户退出 -> paused_session
```

刷新后可以恢复到最近完成的幻灯片和教学步骤，但不自动播放声音。

## 14. PPT 边生成边教学方案

### 14.1 不让模型直接生成可执行页面

Dify 不返回 HTML、JavaScript、SVG 源码或任意 PPTX 文件。Dify 返回受限的 `PresentationPlan` 和 `SlideSpec`，网页使用固定组件渲染，下载版 PPTX 由服务端固定渲染器生成。

允许的幻灯片类型：

```text
title
learning_objectives
concept
comparison
process
code_walkthrough
data_table
chart
image_focus
checkpoint
summary
```

允许的视觉元素来自白名单：标题、项目符号、代码、固定课程图片、数据表、受信图表、箭头流程和像素星宝提示。禁止任意外链脚本和模型生成的可执行组件。

### 14.2 渐进生成流程

1. 应用读取课程 ID、章节、知识点、学生掌握摘要和允许活动。
2. Dify `lesson-presentation-generator` 返回整节课提纲、页数和教学节奏。
3. 应用校验提纲中的课程 ID、知识点 ID、页数、时长和来源。
4. Dify 按页生成 `SlideSpec` 与对应 `NarrationSegment`。
5. 前两页校验并渲染后即可开始教学；后续页面在后台继续生成。
6. 每个语音段落只在对应幻灯片可用后进入播放队列。
7. 生成失败时使用仓库内版本化种子幻灯片，不显示空白画布。
8. 学习结束后，可使用相同已校验内容生成下载版 PPTX。

### 14.3 流事件

Next.js BFF 将 Dify 的流统一转换为以下事件：

```ts
type TutorStreamEvent =
  | { type: "session.started"; sessionId: string; traceId: string }
  | { type: "plan.ready"; plan: PresentationPlanV1 }
  | { type: "slide.ready"; slide: SlideSpecV1 }
  | { type: "narration.delta"; slideId: string; text: string }
  | { type: "narration.segment"; segment: NarrationSegmentV1 }
  | { type: "interaction.ready"; interaction: TutorInteractionV1 }
  | { type: "session.completed"; summary: TutorSummaryV1 }
  | { type: "session.degraded"; reasonCode: string };
```

前端只能处理已知事件；未知事件忽略并记录 trace ID。

### 14.4 语音

- P0 可继续使用浏览器 `speechSynthesis`，后续再接受控中文 TTS。
- 语音以句子或短段落为单位，不朗读 Markdown 符号、代码标点和引用 URL。
- 初中默认语速约 `0.90-0.98`，高中约 `1.0-1.08`，学生可调节。
- 切换幻灯片、学生打断或退出时必须停止当前语音队列。
- TTS 失败时退化为字幕教学，不能阻断课程。
- OrangePi 后续只接收已批准的语音文本或媒体播放任务，不让 Dify 直接控制设备。

## 16. 高中课程体系

高中阶段强调“编写代码、处理数据、训练与评价模型、形成可复核项目”。课程不追求在线训练大型模型，优先使用固定小型数据和可复现实验。

课程 ID：保留 `high-bubble-analysis`

章节：算法正确性、边界条件、比较次数、时间复杂度直觉、测试用例。

### H-05 神经网络与模型训练

课程 ID：保留 `high-neural-network-training`

章节：权重、前向计算、损失、梯度下降、学习率、参数集版本、多轮训练/验证曲线、最佳验证轮次、过拟合与正则化。
实验：在 `weights-init-v1` 和 `training-samples-v1` 固定参数集上运行至少五轮，比较学习率 `0.1` 与 `0.2` 的训练/验证曲线；曲线长度不一致、空曲线或不可复现参数必须拒绝。
确定性判分：`analyze_training_curve(train_losses, validation_losses, learning_rate, parameter_set_id, sample_count)` 必须返回步数、样本数、学习率、参数集 ID、两条原始曲线、最终损失、最佳验证损失及 `best_step`；训练损失下降且最后验证损失高于最佳值时才标记 `overfit_detected=true`。
证据：保存 `loss-curves-v2`、数据集/参数集版本、样本数、轮数、学习率、序列化训练/验证曲线、最佳验证轮次、对照运行指标和正则化限制。

### H-06 计算机视觉与多模态 AI

### 17.3 未成年人数据生命周期

初中和高中默认按未成年人产品处理，首版即按最小化原则设计，不等正式账号系统完成后再补隐私规则：

- **采集**：只保存匿名学习 ID、学段/年级、课程活动 ID、确定性 Evidence、主动填写的笔记和项目作品；不要求姓名、电话、住址、学校班级或家庭信息。
- **发送给 Dify**：只发送裁剪后的 `LearningContextV2`、当前活动所需的指标摘要和必要的短代码片段；发送前去除邮箱、手机号、密钥、URL 查询参数和原始音频。
- **保存期限**：本地演示数据保存在浏览器，提供“清除本机学习数据”；正式服务由服务端配置保留期限，Tutor 原始流和 TTS 音频默认不长期保存。
- **导出与删除**：个人画像提供导出 Evidence/作品 JSON 和“清除本阶段数据”操作；清除必须有二次确认，且不能删除课程版本和系统审计日志。
- **权限**：教师/演示账号只能查看明确授权的匿名摘要；Dify 不接触教师无权查看的原始项目代码和身份信息。
- **审计**：每次外部调用记录 `traceId`、应用版本、课程版本、耗时、降级原因和字段摘要，不记录完整聊天、完整代码或未成年人原始音频。

没有同意或网络不可用时，固定课程、练习、实验和进度仍然可用；AI 导师入口显示离线降级状态，而不是阻塞学习。

## 18. Dify 智能体总体设计

### 18.1 边界

浏览器不得直接访问 Dify。Next.js 服务端 BFF 持有密钥，校验输入、裁剪学习上下文、调用 Dify、验证输出并实施降级。

Dify 可以：

- 按学段进行流式讲解、追问、总结和分级提示。
- 根据权威课程事实生成受限的课程提纲、幻灯片文案和语音讲稿。
- 解释程序已经产生的练习结果、测试失败和实验指标。
- 引导学生组织结论、模型卡和项目报告。
- 根据已提交证据提出答辩问题。

Dify 不可以：

- 决定题目正确答案、代码测试结果、实验指标、掌握度或解锁状态。
- 直接写入学习数据库或 localStorage。
- 返回并执行任意 HTML、JavaScript、Python、Shell 或设备命令。
- 访问未在当前课程和学段过滤范围内的知识库内容。
- 代替学生生成最终研究结论后直接标记完成。

### 18.2 Dify 应用清单

#### A. `k12-learning-dialogue`

类型：Chatflow。
用途：课程内问答、短讲解、追问和适龄提示。
模式：`explain | ask | hint | summarize | review`。
要求：只引用当前课程、当前知识点和检索来源；一次最多提出一个主要问题。

#### B. `lesson-presentation-generator`

类型：Workflow。
用途：生成 `PresentationPlanV1`、逐页 `SlideSpecV1` 和配套讲稿。
要求：严格结构化输出；幻灯片类型、视觉元素、知识点和引用均使用白名单。

#### C. `middle-lab-coach`

类型：Chatflow。
用途：引导初中学生预测、控制变量、观察结果和完善结论。
输入：实验模板、变量、程序指标、测试错误码、提示次数和学生已有结论。
限制：不能计算指标、运行代码或直接给出完整答案。

#### D. `high-project-mentor`

类型：Chatflow。
用途：高中代码实验、数据处理、指标选择、模型卡和项目报告指导。
要求：优先追问“你的证据是什么”；只能引用应用传入的实验运行和项目字段。

#### E. `high-project-defense`

类型：Workflow + Chatflow。
用途：基于已保存项目证据生成 3-5 个答辩问题，并对表达和证据引用给出反馈。
限制：最终通过条件由应用确定性规则判断。

#### F. `learning-path-suggestion`

类型：Workflow，低频调用。
用途：从应用提供的已解锁活动候选中选择建议并生成适龄原因。
限制：不能创建新活动、跨学段推荐或绕过先修条件。

#### G. `exercise-feedback`

类型：Workflow，可并入 `k12-learning-dialogue` 的受控分支。
用途：把确定性判分、误区标签和正确解释转换为适龄反馈。
限制：不重新判题，不改变标准答案。

小学已有战斗出题和反馈工作流不属于本次初高中 UI 重构，不在本任务中修改。

### 18.3 Dify 工作流节点

#### `k12-learning-dialogue`

```text
Start
  -> 读取调用方已验证的 LearningContextV2
  -> 按 stage/courseId/contentVersion 检索知识库
  -> 组合学段教学策略 + 当前课程事实 + 学习证据摘要
  -> LLM 流式讲解或追问
  -> 引用与长度检查
  -> 流式输出
```

输入变量：`traceId`、`stage`、`courseId`、`lessonId`、`activityId`、`mode`、`question`、`masterySummary`、`misconceptionTags`。
输出：流式文本、引用 `sourceIds`、建议的白名单 `actionId` 或结构化错误。
禁止：让 LLM 自己判断当前路由、课程解锁或学生学段。

#### `lesson-presentation-generator`

```text
Start
  -> 获取课程目标和允许知识点
  -> 检索当前课的已审核知识片段
  -> 生成 PresentationPlanV1
  -> 结构和引用预检查
  -> Iteration：逐页生成 SlideSpecV1 + NarrationSegmentV1
  -> 每页检查长度、类型、资产和来源
  -> 按页输出
```

输入变量：`LearningContextV2`、`targetMinutes`、`slideCountRange`、`allowedSlideTypes`、`allowedAssetIds`、`contentVersion`。
输出：一份提纲、4-12 页幻灯片、每页讲稿、2-4 个互动检查点。
禁止：输出任意网页代码、远程图片 URL、没有来源的事实图表或隐藏答案。

#### `middle-lab-coach`

```text
Start
  -> 读取实验模板和当前阶段
  -> 读取程序生成的 variables/metrics/resultCode
  -> 判断学生当前需要 prediction/observation/conclusion 中哪一种提示
  -> 检索对应课程知识点
  -> 生成一个问题或一级提示
  -> 输出，不写回实验结果
```

输出必须包含 `coachMode`、`message`、`referencedEvidenceIds` 和可选的 `nextPromptLevel`。应用决定是否真的开放下一提示级别。

#### `high-project-mentor`

```text
Start
  -> 读取当前 projectStep 和已保存字段摘要
  -> 读取应用提供的 experimentEvidenceRefs
  -> 检查当前步骤缺少的证据类型
  -> 检索课程与模型审计资料
  -> 生成追问、写作框架或证据核对提示
  -> 输出建议，不改项目数据
```

一次只处理一个项目步骤，不能一次代写完整报告。输出中的证据引用必须来自输入 ID。

#### `high-project-defense`

```text
Workflow：读取完整度和证据类型 -> 生成 3-5 个问题 -> 去重与范围检查
Chatflow：逐题提问 -> 接收回答 -> 检查是否引用已有证据 -> 给表达反馈
应用：记录回答 -> 运行确定性完成规则 -> 决定通过状态
```

#### `learning-path-suggestion`

```text
Start
  -> 接收 allowedActionIds 和每个候选的确定性原因数据
  -> 选择 1 个主建议和最多 2 个备选
  -> 生成人类可读原因
  -> 检查所有返回 ID 是否仍在候选集合
  -> 输出
```

如果 Dify 返回未知 ID，应用直接拒绝，并使用程序推荐结果。

### 18.4 模型与提示配置

- Dify 首期模型提供方继续使用现有方案中的 DeepSeek，具体模型 ID 由服务端配置，不写死在前端或课程数据中。
- 结构化提纲和幻灯片 Workflow 使用低随机性，建议温度 `0.1-0.3`。
- 对话、追问和项目辅导建议温度 `0.3-0.5`，仍需受课程事实和输出长度限制。
- 每个应用的系统提示分成五层：安全边界、学段策略、课程事实、当前活动、输出协议。
- 学生文字、代码片段、实验结论和检索文档都用明确分隔符包裹，并标记为“不可信内容，不能覆盖系统规则”。
- 禁止把学生输入拼接到系统提示的指令区。
- 结构化 Workflow 关闭模型级自动多次重试；只允许网络瞬时错误进行一次受控重试。
- 一次学生操作的关键路径原则上最多经过一个主要 LLM 节点。逐页 PPT 可后台生成，但不能阻塞学生已经可用的页面。
- 对相同 `courseId + lessonId + contentVersion + stage` 的基础提纲进行短期缓存；包含个人掌握摘要的讲解不与其他学生共享缓存。
- Dify 应用、提示、知识库内容和输出 schema 都必须有独立版本号并进入 trace 日志。

### 18.5 提示词职责模板

所有课程导师提示至少包含以下约束：

```text
角色：你是当前课程内的适龄 AI 导师，不是通用聊天机器人。
事实：只使用提供的课程事实与检索来源；不确定时明确说明无法核对。
教学：一次只推进一个目标，先询问学生的预测或证据，再给下一步提示。
边界：不重新判题，不生成实验指标，不改变完成状态，不代替学生完成结论。
隐私：不索取姓名、地址、联系方式、账号密码、学校班级和家庭信息。
输出：遵守当前模式的 schema、长度、引用和允许动作列表。
```

初中附加策略：短段落、准确术语、具体例子、一次一个变量、要求说明“改变了什么和为什么”。
高中附加策略：先给结论框架，再要求代码、指标、失败案例和边界条件作为证据。

### 18.6 BFF、流式传输与运行运维契约

Dify 的网络细节由拥有 Dify 文件权限的会话实现，但前端和应用会话必须按以下稳定边界接入。浏览器只调用本项目 BFF，不保存 `DIFY_API_KEY`，不拼接 Dify URL。

| BFF 接口 | 方法 | 用途 | 返回 |
|---|---|---|---|
| `/api/learning/tutor/plan` | `POST` | 预生成课程提纲和前两页 | `PresentationPlanV1` + `slide.ready` |
| `/api/learning/tutor/stream` | `POST` | 讲稿、互动点和后续幻灯片流 | `TutorStreamEvent`（SSE 或等价流） |
| `/api/learning/tutor/session/:id` | `GET` | 刷新恢复最近已确认状态 | 已校验的 session snapshot |
| `/api/learning/tutor/session/:id/cancel` | `POST` | 取消生成和语音队列 | `session.degraded` 或 `session.cancelled` |
| `/api/learning/tutor/tts` | `POST`（P1） | 将已批准的讲稿交给受控 TTS | 音频引用和过期时间；P0 不调用 |

运行约束：

- BFF 在入口校验 `stage/courseId/lessonId/activityId/contentVersion`，在出口校验事件类型、schema、来源 ID、资产 ID、`dataRef` 和长度；未知字段丢弃而不是透传。
- `plan` 首包目标不超过 3 秒；`stream` 超过 8 秒没有有效事件或连续两次 schema 失败，切换仓库内静态种子课程并记录降级原因。
- 生成会话使用短 TTL（建议 30 分钟）；断线重连只重放已确认的 `slide.ready`/`narration.segment`，不能重复写入 Evidence。取消必须同时中止 Dify 请求和浏览器语音队列。
- 同一匿名学习者对导师流、PPT 生成和 TTS 分别限流；首期建议每分钟 6 次对话、每小时 20 次 PPT 计划、每分钟 2 次 TTS。限流后仍可进入静态课。
- `traceId`、`sessionId`、`contentVersion`、`difyAppVersion`、耗时、token 用量摘要和降级原因进入结构化日志；不记录完整提示词中的身份信息、完整代码、原始音频或完整聊天。
- Dify 只生成讲稿文本，不直接生成音频文件。P0 使用浏览器 `speechSynthesis`；P1 TTS 由独立服务生成短期缓存音频，前端只拿受限引用，过期后重新申请。
- PPTX 导出使用服务端固定渲染器：16:9、页数 4-12、单页最多 8 个 block、中文字体回退链固定；图表只能引用应用生成的 `dataRef`，不能让模型传入外链或任意 SVG。

## 21. 学习状态与数据模型

建议把当前课程数据逐步正规化为以下概念：

```text
Stage
  -> Course
    -> Unit
      -> Lesson
        -> Activity
          -> Evidence
          -> Artifact
          -> TutorSession
```

### 21.1 关键实体

- `Course`：课程元数据、目标、封面、预计时长和适用学段。
- `Unit`：课程内主题分组。
- `Lesson`：一次 10-25 分钟学习单元。
- `Activity`：讲解、示范、练习、编程、实验、项目或答辩。
- `Evidence`：答题、代码测试、实验运行和项目字段的确定性记录。
- `Artifact`：学生保存的代码、实验报告、模型卡或项目报告。
- `TutorSession`：AI 导师进度、当前幻灯片、提问和降级状态。

### 21.2 存储规则

- 首期继续兼容浏览器本地存储，但新实体必须有 schema 版本、数量上限和迁移测试。
- 正式业务真源后续迁移到 FastAPI Core；本地存储转为离线缓存。
- 不把 AI 自由文本直接当作掌握证据。
- 不把学生完整项目代码混入普通学习状态。
- 任何未知课程、活动、知识点、模板和策略 ID 在解析时丢弃。

## 23. 分阶段实施任务

## 24. 测试与验收标准

### 24.1 功能验收

- 学段切换不会丢失进度。
- 小学入口仍能回到现有地图。
- 初高中路径、课程、练习和画像使用同一学习状态。
- 锁定节点说明真实缺失条件。
- 所有客观题、代码和实验结果确定性可复现。
- AI 导师不能修改答案、分数、指标和解锁。
- PPT 页面、字幕、语音和互动顺序一致。
- Dify 不可用时可以继续固定课程和本地练习。

### 24.2 视觉验收

- 1440x900 与 1920x1080 下无横向滚动。
- 顶栏、侧栏和工作区不互相遮挡。
- 课程卡在两列和三列之间稳定切换。
- 题目、长课程名和中文标点不会溢出。
- 代码编辑器、输出和任务栏不会因状态变化改变主布局尺寸。
- AI 导师幻灯片保持稳定 16:9，不被流式字幕挤压。
- 不使用大面积单色渐变、过多圆角卡片或卡片套卡片。

### 24.3 可访问性验收

- 学段切换具有 `aria-pressed` 或正确 tab 语义。
- 侧栏有当前页面状态。
- 课程卡、路径节点和练习选项可使用键盘。
- 练习反馈使用 `aria-live`，但不会重复朗读整页。
- AI 导师具备字幕、暂停、停止语音和减少动态效果支持。
- 颜色不是唯一状态信号。

### 24.4 Dify 验收

- 输入 ID 和枚举均由服务端校验。
- 输出通过严格 schema 后才能进入页面。
- 检索严格过滤学段、课程和版本。
- 首段文本 P95 目标不高于 2.5 秒。
- 前两页幻灯片准备后开始教学，目标等待不高于 6 秒；超过上限进入种子课程。
- 8 秒没有有效内容时终止当前生成并降级。
- 记录应用 ID、工作流版本、模型、耗时、结果类型和降级原因。
- 日志不保存未成年人身份、原始音频、完整代码和不必要的完整对话。

```ts
};
```

普通课程 manifest（`kind: "course"`）至少需要一个 Unit、两个 Lesson、三个 Activity；每个知识点一条审核过的讲解事实和一条可判定练习；涉及代码/实验时必须有固定模板、测试向量、超时、重置、结果码和失败补救。`H-09` 使用 `kind: "project-only"`、`courseId: null`、`projectId: "high-capstone-project"`，只出现在高中课程目录的项目分组和路径中，不计入普通课程完成数。内容 manifest 的最低审核字段如下：

| 字段 | 生产要求 | 页面用途 |
|---|---|---|
| `officialMappings` | 对应官方章节/能力要求；未知时明确 `draft` | 课程详情显示来源和审核状态 |
| `objectiveIds` | 可观察动词，如“计算”“比较”“解释” | 学习路径和课程目标 |
| `promptIds` | 题干、选项、标准答案、误区标签和解析 | 练习/错题补救 |
| `templateId` | 代码入口、依赖白名单、固定输入和测试 | 编程实验室 |
| `evaluationPolicyId` | 纯函数判分/指标/完成条件版本 | Evidence 和解锁 |
| `remediationActivityIds` | 与失败原因一一对应，不能只有“重试” | 练习反馈和个人画像推荐 |
| `sourceIds` | 教师审核资料、比赛材料或权威来源 | Dify 引用和审计 |

推荐的官方映射表独立保存为 `docs/official-ai-literacy-mapping.csv`，列为：`officialChapterId, officialRequirement, stage, gradeRange, courseId, unitId, lessonId, activityId, evidenceRuleId, sourceId, mappingStatus, reviewer, reviewedAt`。拿到正式《人工智能通识课》文件后，先补这张表和 manifest，再批量生成页面内容。

## 31. 页面级 UI 规格

### 31.1 统一学习大厅 `/learn`

**顶栏（64px）**

- 左：星宝/项目品牌、返回小学地图或首页。
- 中：三段式学段切换器，切换前保留当前学习状态。
- 右：搜索、进度入口、匿名档案菜单。
- 不把 AI 导师做成与学习路径同级的第五个侧栏页面；导师是课程内模式。

**侧栏（224-240px）**

- 学习路径：章节时间线、继续学习、解锁原因。
- 课程：课程卡、搜索、主题筛选。
- 练习：每日练习、专题、编程挑战、错题补救。
- 个人画像：掌握度、误区、实验、作品和复习。
- 底部只放一个星宝状态入口，不同时堆放等级、积分和排行榜。

**内容区**

- 工作区背景使用浅灰/白色；工具面板可使用中性深色。
- 课程卡圆角不超过 6px，使用边框区分，不使用卡片套卡片。
- 1440px 为两列，1920px 为三列；代码和图表页面改用三栏工作台。
- 每个按钮必须是明确动作；图标按钮使用 Lucide 并提供 tooltip。

### 31.2 课程目录和卡片

课程卡的固定字段：课程类别、标题、目标一句话、难度、时间、章节数、形式图标、进度、状态、主要动作、AI 导师动作。卡片不显示没有样本依据的“推荐指数”或虚构分数。

课程详情必须把 `Unit -> Lesson -> Activity` 展示成可恢复的目录。未满足前置条件时显示缺失证据和“去完成”入口；已完成内容可以回看，但不能用回看绕过必修评价。

### 31.3 练习页

参考第二张截图的单题节奏，但不复制其品牌：顶部显示题组进度，主体显示题干/代码/数据，下方显示大面积选项，底部显示提交、提示和退出。支持键盘 `1-4`，提交后先由程序判分，再显示解释、知识点和补救入口。反馈通过 `aria-live` 发布，不能把整页重复朗读。

### 31.4 AI 导师页

参考第三张截图的三栏课堂：左侧为导师字幕和学生提问，中间为稳定的 16:9 幻灯片/代码画布，右侧为进度、笔记和控制。参考第一张截图的顶部学习壳层，但不复制 DataCamp 的品牌、颜色、文案或素材。

- 进入前显示目标、预计时间、语音开关和“使用固定课程”选项。
- 字幕按短句流式输出，语音按完整句排队；暂停时同时停止语音和生成。
- 每 2-4 页出现一个预测、选择、代码观察或短回答互动。
- 互动答案和练习分数由应用规则判断，AI 只解释。
- 语音失败退化为字幕，Dify 失败退化为本地种子幻灯片，刷新后不自动播放声音。
- `prefers-reduced-motion` 时关闭折叠、扫描线和非必要转场。

### 31.5 编程/实验页

固定三栏：左侧任务、数据、提示；中间 Monaco 编辑器；右侧测试、stdout/stderr、指标和运行记录。底部工具栏固定放运行、停止、重置、保存版本、询问星宝。编辑器、输出区和指标区使用稳定尺寸，避免运行状态导致页面跳动。

### 31.6 个人画像页

画像只展示可追溯学习证据：掌握度、证据次数、误区、复习、实验记录、项目作品和推荐原因。没有足够样本时显示“证据不足”，禁止推断智力、性格、心理或医学标签，也不公开学生排名。

## 32. Dify 智能体实施规格

### 32.1 智能体清单

| 应用 ID | 类型 | 负责内容 | 不得做什么 |
|---|---|---|---|
| `k12-learning-dialogue` | Chatflow | 课程讲解、追问、总结、错题解释 | 不判题、不解锁、不改分 |
| `lesson-presentation-generator` | Workflow | 提纲、幻灯片、讲稿、互动点 | 不输出 HTML/JS/可执行 SVG |
| `middle-lab-coach` | Chatflow | 预测、单变量实验、结论提示 | 不运行代码、不计算指标 |
| `high-project-mentor` | Chatflow | 代码、指标、模型卡、报告提问 | 不代写完整结论、不写项目状态 |
| `high-project-defense` | Workflow + Chatflow | 生成 3-5 个答辩问题和表达反馈 | 不决定答辩是否通过 |
| `learning-path-suggestion` | Workflow | 在已解锁候选中选下一步 | 不创建新 ID、不跨阶段推荐 |
| `exercise-feedback` | Workflow/受控分支 | 把确定性判分翻译成适龄反馈 | 不重新判题、不改答案 |

### 32.2 调用链

```text
浏览器 -> Next.js BFF -> 输入校验/脱敏/限流 -> Dify
      <- 事件校验/白名单过滤/降级 <-
```

浏览器不能保存 Dify 密钥或直连 Dify。BFF 必须校验 `stage/courseId/lessonId/activityId`、枚举、长度和 `allowedActionIds`，并只发送匿名学习摘要、程序结果和必要的短代码片段。

### 32.3 `LearningContextV2` 最小必需字段

```ts
type LearningContextV2 = {
  schemaVersion: 2;
  traceId: string;
  anonymousLearnerId: string;
  stage: "middle_school" | "high_school";
  grade: number | null;
  courseId: string;
  unitId: string;
  lessonId: string;
  activityId: string;
  teachingMode: "self_study" | "ai_tutor" | "practice" | "lab" | "project" | "defense";
  knowledgePointIds: string[];
  masterySummary: Array<{ knowledgePointId: string; level: number; evidenceCount: number }>;
  misconceptionTags: string[];
  recentEvidenceSummary: Array<{ evidenceId: string; kind: string; resultCode: string; metricSummary?: Record<string, number> }>;
  allowedActionIds: string[];
};
```

### 32.4 受限输出

PPT 和教学内容只允许返回经过 schema 校验的 `PresentationPlanV1`、`SlideSpecV1`、`NarrationSegmentV1`、`TutorInteractionV1`。`slide.type`、`block.kind`、`assetId`、`dataRef`、知识点 ID 和来源 ID 必须来自应用白名单。未知事件、未知动作和未知资源直接丢弃并记录 `traceId`。

### 32.5 流式教学状态

```text
idle -> planning -> prebuffering -> presenting
     -> awaiting_interaction -> presenting
     -> summarizing -> completed

任一生成失败 -> degraded_static_lesson
语音失败 -> text_only
用户退出 -> paused_session
```

前两页幻灯片准备好即可开课，后续页面后台生成。超过 8 秒没有有效事件，或 schema 校验连续失败，切换到仓库内静态种子课程。降级状态仍允许练习、实验和学习证据写入。

### 32.6 提示词五层结构

每个 Dify 应用的系统提示固定包含：

1. 安全边界：不索取未成年人隐私，不执行代码或设备命令。
2. 学段策略：初中短句、具体例子和一次一个变量；高中优先证据、指标和限制。
3. 课程事实：仅使用已审核的课程片段和当前版本。
4. 当前活动：目标、知识点、程序结果、允许提示级别。
5. 输出协议：模式、长度、引用、允许动作和错误码。

学生输入、代码、实验结论和检索文档必须标记为不可信内容，不能覆盖系统规则。Dify 返回的建议动作必须再次与 `allowedActionIds` 求交集。

## 33. 确定性学习和 AI 的责任分界

| 能力 | 程序负责 | Dify 负责 |
|---|---|---|
| 题目正确答案 | 维护标准答案和判分 | 用适龄语言解释结果 |
| 代码测试 | 执行固定测试、超时、输出限制 | 解释报错和提出下一步问题 |
| 实验指标 | 由固定引擎计算 | 解读趋势，询问结论依据 |
| 解锁和阶段完成 | 依据 Evidence 和策略纯函数判断 | 说明缺少条件，不能绕过 |
| PPT/语音 | 渲染白名单页面、播放和暂停 | 生成受限文案和讲稿 |
| 项目通过 | 检查字段、引用、测试和答辩证据 | 提问和给表达反馈 |

任何无法由程序复核的开放回答只能形成“待复核/表达反馈”记录，不能单独提升掌握度或解锁高中。
