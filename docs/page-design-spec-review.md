# Mambo K12 AI Robot 页面设计说明（审查稿）

> 版本：v0.2-review  
> 文档用途：先由产品/项目负责人审查页面范围、功能和视觉方向；确认后再调用前端设计技能进行实现。  
> 当前代码基线：`apps/web` 已有学生端原型，服务端为 FastAPI + OrangePi 设备代理。  
> 本文不是最终视觉稿，也不替代 Figma 组件标注。

## 1. 产品一句话

Mambo K12 AI Robot 是一个把 AI 对话、课程内容、动画/绘本、编程练习、学习记录和 OrangePi 实体设备连接在一起的 K12 多模态学习工作台。

网页负责课程和学习流程，OrangePi 负责摄像头、麦克风、扬声器、屏幕和实体交互。学生进入网页后应直接开始学习，不使用营销型落地页作为首屏。

## 3. 整体设计风格

### 3.1 风格定位

**近未来 AI 教室 / 技术感学习工作台**。

它应该让人感觉“这是一个真实的 AI 教学控制台”，而不是普通教务后台，也不是儿童游戏首页。技术感来自信息组织、实时状态、教学画布和设备能力，而不是堆叠发光渐变或 3D 装饰。

### 3.2 色彩方向

- 基础底色：暖白、雾灰或浅石墨，保证长时间阅读舒适。
- 主交互色：电光青/深青，用于选中、连接、可执行动作和教学进度。
- 辅助色：薄荷绿表示成功或已掌握，琥珀色表示进行中/提醒，珊瑚红表示失败/需要帮助。
- 文字色：深石墨、次级灰、弱化灰；代码和设备指标使用深色等宽字体。
- 不使用大面积紫色渐变，不使用装饰性光球、模糊光斑或无法解释的背景纹理。

### 3.3 排版和密度

- 中文正文使用清晰的无衬线字体，标题不使用夸张的展示字体。
- 设备 ID、命令状态、版本号、CPU/内存/温度等使用等宽字体，强化“设备正在运行”的感觉。
- 桌面端采用中高信息密度，方便快速比较课程、状态和学习记录。
- 移动端不压缩桌面三栏，改成清晰的标签页和单列内容。
- 不随视口宽度缩放字号；卡片、工具栏、画布和数值区域有稳定尺寸。

### 3.4 形状、边框和动效

- 卡片圆角控制在 4～8px，页面区块使用平面分区，不使用卡片套卡片。
- 使用细边框、局部阴影和色块分区，不使用厚重玻璃拟态。
- 动效只表达状态变化：消息流入、命令排队、动画单步、练习反馈、设备连接变化。
- 所有长任务显示 `queued -> running -> success/failed`；失败必须可重试。
- 支持减少动态效果、键盘操作、字幕和朗读控制。

## 4. 个性化设计元素

这些元素是 Mambo 与普通 AI 聊天页的差异点，后续前端设计应优先保留。

### 4.1 学段适配，不只是换颜色

支持小学低年级、小学高年级、初中、高中四个学段。学段切换会影响：

- 课程卡片的内容长度和信息密度；
- AI 回答的句子长度、术语解释和追问方式；
- 教学画布默认类型，例如低龄优先绘本/动画，高中优先代码/变量/引用；
- 练习提示阶梯和反馈语言；
- 语音、字幕、大按钮和键盘操作的优先级。

学段切换器是工作台中的固定控件，不能藏在设置页。

### 4.2 “学习 DNA”兴趣画像

学生可以选择机器人、编程、太空、自然、游戏等兴趣标签。兴趣标签用于：

- 课程推荐文案和示例替换；
- AI 课堂中的类比素材；
- 进度页的下一课推荐原因；
- 作品集的主题筛选。

兴趣不是装饰头像，也不直接改变成绩。用户应能在进度页查看和修改。

### 4.3 三栏教学工作台

桌面端的核心视觉识别：

```text
课程路径          对话课堂                         教学画布
今日目标          学生与 AI 消息                   动画、绘本、材料、代码、练习
章节步骤          快捷追问、文本/语音/图片输入       播放、单步、最大化、重试
学习状态          引用、反馈、会话状态              作品保存和设备展示
```

三栏不是三个独立页面，而是同一学习会话的三个视角。打开画布不能清空对话；最大化后返回应保留位置。

### 4.4 教学画布和“可操作内容”

右侧画布不是静态图片预览，而是可以操作的学习对象：

- 冒泡排序：数组、比较、交换、轮次、比较次数，支持播放/暂停/单步/速度。
- 神经网络：输入、特征、隐藏层、输出概率，支持高亮信号流和解释文本。
- 绘本：分页、朗读、暂停、页内问题和重新播放。
- 编程：代码、运行、输出、错误、测试、提示和重置。
- 练习：题目、选择/排序/追踪、提交、反馈和下一题。

### 4.5 可信来源和学习证据

锚点课程中的事实使用 `[S#]` 来源标记，点击后展开来源名称、链接和说明。进度页展示“哪一次回答/练习形成了记录”，而不是只给一个无法解释的分数。

### 4.6 OrangePi 实体终端状态

网页顶部或设备页展示设备在线状态和能力标签：摄像头、显示器、音频输入、音频输出、NPU。设备不在线时明确切换为“网页模式”，不隐藏错误，也不把离线状态伪装成成功。

设备控制只允许白名单教学命令：拍照、显示媒体、停止媒体、播放/停止音频、屏幕 on/presentation/off。页面不提供 SSH、Shell、任意路径或任意程序输入。

## 5. 页面详细说明

### 5.1 学习工作台 `/`

**页面目标**：学生登录后的默认学习空间，完成一节课的主要流程。

### 页面结构

1. 顶部产品栏：品牌、主导航、当前学段、设备状态、个人入口。
2. 学段工具栏：四个学段切换，显示当前学段和简短说明。
3. 左栏“课程路径”：课程标题、课程摘要、章节时间线、已完成/当前/待学习状态。
4. 中栏“对话课堂”：消息、引用、快捷问题、输入区、语音/图片入口、发送状态。
5. 右栏“教学画布”：材料、动画、绘本、代码、练习标签和对应操作区。
6. 移动端底部导航：路径、对话、内容三个标签。

### 核心功能

- 选择学段和课程；记录最近课程。
- 创建或恢复学习会话。
- 发送文本、图片或语音输入；AI 回答支持流式显示或清晰的降级状态。
- 在画布中切换课程内容类型。
- 开始、暂停、重试动画；完成练习并写入学习记录。
- 保存绘本/作品，下载 DOCX/PPTX 等材料。
- 会话结束时选择“完成”或“稍后继续”。

### 页面状态

- 首次进入：显示推荐课程和“开始第一节课”。
- 恢复学习：显示上次章节、未完成消息和继续按钮。
- AI 生成中：消息区显示排队/生成，画布显示占位状态。
- AI 失败：保留已输入内容，提供重试和课程内备用解释。
- 设备离线：切换为网页模式，设备按钮禁用但学习仍可继续。
- 低龄模式：大目标按钮、更多朗读和视觉材料、较少同时显示的信息。
- 高中模式：引用、代码、变量状态和扩展问题默认展开。

### 5.2 学习进度 `/progress`

**页面目标**：回答“我学过什么、哪里需要复习、下一步学什么”。

### 页面内容

- 顶部学生概览：学段、兴趣标签、最近学习时间、连续学习天数（有真实数据才显示）。
- 知识点掌握区：按课程/知识点展示已掌握、练习中、待复习；缺少聚合数据时显示记录数量而不是虚构百分比。
- 学习历史：课程、日期、会话状态、练习数、得分和回看入口。
- 错题与反馈：错误知识点、原题、反馈、推荐补救课程。
- 下一课推荐：推荐课程、推荐原因、开始学习按钮。
- 兴趣设置：添加/删除兴趣标签，修改后立即影响后续推荐。
- 作品入口：绘本、代码作品、动画记录。

### 个性化元素

- 用“学习路径”表达进度，不用单一大圆环作为唯一成绩。
- 每条推荐必须有原因，例如“最近两次在‘特征’知识点上需要提示”。
- 错题反馈用“误区 -> 提示 -> 再练习”三步，而不是只显示红色错误。

### 5.3 编程实验室 `/lab`

**页面目标**：让学生在受控环境中理解算法、运行 Python 代码并获得形成性反馈。

### 页面结构

- 左侧挑战列表：当前课程、挑战目标、难度、完成状态。
- 中央编辑区：Monaco Python 编辑器，带运行、停止、重置。
- 右侧结果区：标准输出、错误、测试结果、提示阶梯和知识点解释。
- 底部运行状态：准备、运行中、已完成、失败、已停止。

### 核心功能

- 载入固定课程模板，不默认打开空白编辑器。
- 运行代码，显示输出和确定性挑战检查。
- 运行超时可以停止；输出过长要截断并说明。
- 提供分层提示：思路提示、局部提示、示例修复；避免直接替学生完成。
- 重置到课程初始代码；挑战完成后写入形成性学习证据。

### 安全和体验要求

- 运行环境为浏览器隔离 Worker/Pyodide，不向学生暴露服务端密钥。
- 明确提示这是课程练习沙箱，不是正式考试判题。
- 移动端显示结果优先，代码区可折叠，不强行显示三栏。

### 5.4 OrangePi 课堂 `/robot`

**页面目标**：为 800×480 屏幕提供简洁、可操作的实体机器人课堂界面。

### 页面内容

- 顶部设备状态：设备名、在线/离线、最近心跳、当前课程。
- 中央教学内容：当前画布的图片、动画、绘本页或提示。
- 底部大按钮：上一页、下一页、播放/暂停、朗读、确认、返回。
- 语音状态：待机、录音、识别中、回答中、播放中、失败。
- 手势状态：追踪中、指针移动、悬停确认、跟踪丢失。
- 设备动作：拍照、显示媒体、播放/停止音频、屏幕模式。

### 设计约束

- 只保留当前任务和最多两个次级动作，不复用桌面端密集三栏。
- 所有触控目标大于普通桌面按钮，文字和图标同时提供。
- 不显示完整管理日志；诊断信息进入 `/devices`，不是机器人课堂。
- 设备离线时显示“网页模式”，保留课程阅读和退出操作。

### 5.5 登录和身份选择 `/login`（P1）

**页面目标**：为正式身份系统预留入口，当前可先作为演示身份选择。

### 页面内容

- Mambo 品牌和一句教育定位，不做营销型 Hero。
- 学生、教师、管理员身份入口。
- 演示账号/环境选择（仅开发环境）。
- 连接状态、隐私说明和服务不可用提示。

### 约束

- 不在浏览器存储管理令牌、设备令牌、模型密钥或 Provider 密钥。
- 登录成功后按角色进入学习、教师或设备工作台。
- 真实身份、RBAC、资源归属和会话过期由后续服务端实现。

### 5.6 课程库 `/learn/courses`（P1）

**页面目标**：让学生按学段、兴趣和学习状态浏览课程。

### 页面内容

- 学段筛选、兴趣筛选、课程搜索。
- 课程卡片：标题、摘要、知识点、预计时长、当前进度、推荐原因。
- 课程详情：章节列表、学习目标、材料、练习和继续按钮。
- 已完成、学习中、未开始三种状态。

课程库与首页“今日学习”不同：首页回答“现在做什么”，课程库回答“我可以学什么”。

### 5.7 作品集 `/learn/storybooks`（P1）

**页面目标**：保存和回看学生生成的绘本、动画和代码作品。

### 页面内容

- 按作品类型、课程和创建时间筛选。
- 作品缩略图、标题、课程、创建时间、状态。
- 详情页支持播放、朗读、重新生成、分享预览和删除确认。
- 生成失败作品显示错误原因和重试，不显示空白卡片。

### 5.8 练习和错题 `/learn/practice`（P1）

**页面目标**：把练习变成可解释的补救路径，而不是排行榜。

### 页面内容

- 今日练习、错题本、知识点筛选、推荐练习。
- 单选、排序、代码追踪等 P0 题型。
- 答题后显示正确性、误区说明、分层提示和下一步。
- XP/徽章可以作为轻量反馈，但不能替代掌握度和正式学习记录。

### 5.9 设备中心 `/devices`（P1）

**页面目标**：管理端查看 OrangePi 状态并执行安全的教学设备命令。

### 页面内容

- 设备列表：设备 ID、在线状态、最后心跳、代理版本、平台。
- 能力标签：摄像头、显示器、音频输入/输出、NPU。
- 设备详情：状态快照、硬件能力、状态历史、播放器状态。
- 控制台：刷新状态、拍照、显示/停止媒体、播放/停止音频、屏幕模式。
- 命令历史：`sent`、`completed`、`failed`、`timed_out`、耗时、错误码和重试。
- 拍照结果：尺寸、文件大小、时间和受管媒体预览。

### 安全边界

- 前端不提供 Shell、SSH、任意 URL、本地路径或任意程序。
- 离线设备不能发送命令；命令失败时保留审计结果。
- 设备令牌和 Core 管理令牌只由服务端 BFF 使用。

### 5.10 教师和管理端（P2）

### `/teacher/courses` 课程管理

- 课程、单元、课时和知识点列表。
- 草稿、预览、发布、归档和版本记录。
- 按学段检查内容是否符合年龄层。

### `/teacher/resources` 资源中心

- 上传视频、PDF、DOCX、PPTX、图片和音频。
- 扫描、解析、索引、审核、发布和失败重试。
- 资源引用回链到学生课堂。

### `/teacher/students` 学生分析

- 学生学习路径、薄弱知识点、练习反馈和作品。
- 关注“为什么推荐”，不只显示单一排名。

### `/teacher/content-jobs` 生成任务

- 任务排队、生成中、可预览、失败、重试、审核、发布。
- 展示来源、Provider、版本和操作审计。

### `/admin/providers`、`/admin/audit`

- Provider、模型、ASR/TTS、媒体服务的版本和健康状态。
- 内容安全、调用链、设备命令和管理员操作日志。

## 6. 全局组件和交互语言

后续视觉设计应围绕这些可复用组件，而不是每页重新画一套：

| 组件 | 用途 | 关键状态 |
|---|---|---|
| `AppShell` | 顶部导航、品牌、设备状态 | 当前页、设备离线、窄屏折叠 |
| `StageSwitcher` | 学段切换 | 小学低/小学高/初中/高中 |
| `CourseRail` | 课程章节路径 | 已完成、当前、锁定、推荐 |
| `ConversationClassroom` | 消息、引用、输入 | 生成中、失败、重试、只读 |
| `TeachingCanvas` | 动画/绘本/代码/练习 | 空、加载、可操作、完成 |
| `EvidenceChip` | 来源和学习证据 | 可点击、来源缺失、已验证 |
| `DeviceStatus` | OrangePi 在线状态 | 在线、离线、连接中、能力缺失 |
| `CommandLog` | 设备命令历史 | 已发送、成功、失败、超时 |
| `ProgressPath` | 学习路径和复习 | 完成、进行中、待复习、推荐 |
| `FeedbackPanel` | 错题/运行/AI 反馈 | 正确、误区、提示、下一步 |

全局状态必须覆盖：`loading`、`empty`、`offline`、`queued`、`running`、`success`、`failed`、`permission denied`。不能只设计成功态。

## 7. 不做的事情

- 不制作首屏营销 Landing Page。
- 不把每个功能都做成悬浮卡片或大 Hero 区。
- 不用虚假的掌握率、设备在线状态、AI 完成状态或生成结果。
- 不在前端保存 API Key、管理令牌、设备令牌或 Knodo 凭据。
- 不给模型输出开放任意 Shell、任意路径或任意程序执行能力。
- 不在首轮原型中塞入完整教师 CMS、Provider 控制台、资源解析后台和审计系统。
- 不因为安装了 AMap 技能就强行增加地图页面；当前产品没有地图核心场景。

## 8. 首轮审查重点

请先确认以下决策，再进入前端设计和实现：

1. 默认首页是否确定为学生学习工作台 `/`，而不是先做登录页或设备控制台？
2. 整体视觉是否采用“明亮教育底色 + 深色设备/代码区域 + 电光青强调”的近未来方向？
3. OrangePi 是否需要在学生首页常驻显示状态，还是只在 `/robot` 和 `/devices` 显示？
4. 首轮是否只做 P0 四页，还是同时加入 `/login`、`/devices` 和课程库？
5. 四学段是否使用不同的信息密度和默认画布，而不是只更换颜色？
6. 作品集、排行榜、XP/徽章是否保留为辅助功能，不作为核心学习评价？
7. 教师端是下一阶段页面，还是本轮需要一起做导航和空状态？
8. 是否需要真实地图场景？如果没有，AMap 技能暂不参与本项目页面设计。

## 9. 审查通过后的执行顺序

1. 根据本稿确定页面优先级和视觉方向。
2. 调用 `taste-skill`、`ui-ux-pro-max`、`antfu-design` 和 `web-design-guidelines` 形成设计方案与检查清单。
3. 对已有 `/`、`/progress`、`/lab`、`/robot` 做视觉统一和交互补齐。
4. 先完成学生 P0 闭环，再实现设备中心和教师端。
5. 用桌面和移动端截图检查布局、文字溢出、状态覆盖和可访问性。
