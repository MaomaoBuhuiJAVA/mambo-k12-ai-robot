# Mambo K12 AI Robot：Stitch 页面功能说明

> 版本：v0.1 草案  
> 依据：项目提交 `1d02efa`（2026-07-18）及现有产品技术设计  
> 用途：作为 Google Stitch 的页面生成输入，也作为后续前端开发的功能边界说明。

## 1. 当前项目进度

### 1.1 已经具备的后端和设备能力

- FastAPI 服务端已经可以管理 OrangePi 设备的在线状态、心跳、状态历史和硬件能力。
- OrangePi 通过带鉴权的 WebSocket 主动连接服务端，支持断线重连和 systemd 守护。
- 设备端已经有安全的白名单命令闭环：`ping`、`get_status`、`capture_snapshot`、`show_artifact`、`stop_artifact`、`play_audio`、`stop_audio`、`set_display_mode`。
- 摄像头、显示器、音频、NPU 和 `ffmpeg`/`mpv`/`xset` 工具能力会被探测并持久化。
- 服务端会保存命令状态、完成结果、失败原因和超时状态；设备端不执行任意 Shell。
- 学生档案支持四个学段：小学低年级、小学高年级、初中、高中，并支持兴趣标签。
- 课程支持按学段管理。创建学习会话时会校验学生和课程的学段是否匹配。
- 学习会话支持消息、消息多模态元数据、练习作答、得分和反馈的持久化。
- 开发环境使用 SQLite，生产环境可切换 PostgreSQL；项目已有迁移、OpenAPI 和自动化测试基础。

### 1.2 当前还没有实现的部分

- 仓库中目前没有 `apps/web` 或其他前端目录，Stitch 生成的是前端原型/页面起点，不是已有页面的改版。
- 真实用户登录、角色权限和学生/教师身份归属尚未接入；当前 API 使用管理令牌。
- Knodo、模型 Provider、真正的流式 AI 对话、ASR/TTS、RAG 知识库和异步生成任务尚未接入。
- 设备配对、共享学习会话、语音输入、连续视频和 NPU 视觉事件尚未形成完整产品流程。
- 掌握度聚合、推荐原因、教师统计、资源上传审核、编程沙箱等页面需要后续 API 支持。

**阅读本说明时，凡标注“当前可接入”的功能才应视为已有后端基础；标注“规划中”的功能先做页面结构和状态，不要假装已经有真实数据。**

## 2. 产品定位和设计目标

这是一个面向 K12 的多模态 AI 教学工作台。网页是主产品，OrangePi 是带摄像头、麦克风、扬声器和屏幕的实体交互终端。登录后的第一屏直接进入学习工作台，不制作营销型 Landing Page。

Stitch 首轮应生成一个可以演示“选择学生/课程 -> 开始学习会话 -> 对话并查看教学内容 -> 查看学习记录 -> 控制机器人设备”的产品界面。

视觉方向：科技感教育工作台，而不是普通后台管理系统。建议使用深色石墨色或浅色高对比底色，搭配电光青色、薄荷绿和少量琥珀色状态色；信息密度适中，强调清晰层级、实时状态和可操作反馈。不要使用大面积渐变、营销式英雄区、装饰性卡片堆叠或不可解释的 3D 效果。

## 3. 用户角色

| 角色 | 首要任务 | 首轮页面 |
|---|---|---|
| 学生 | 继续课程、与 AI 对话、完成练习、查看进度和作品 | 学习首页、学习会话、进度 |
| 教师 | 创建课程、查看学生状态、准备教学内容 | 课程管理、学生/分析（规划中） |
| 管理员 | 查看设备、发送硬件命令、排查连接和命令失败 | 设备管理 |
| OrangePi | 执行拍照、显示、播放和屏幕控制 | 设备端，不是本轮网页主页面 |

## 5. 页面功能说明

### 5.1 `/login` 登录/演示身份选择

**目的**：让 Stitch 有明确入口，但不制作宣传页。

**功能**：

- 显示产品名“Mambo K12 AI Robot”和简短的教育定位。
- 提供学生、教师、管理员三种演示身份入口；页面上明确这是演示身份，不代表真实鉴权已完成。
- 记住上次选择的身份，并根据身份进入对应工作台。
- 显示连接环境提示，例如“本地开发 API / 设备在线”。

**状态**：加载、连接失败、身份选择成功、服务不可用。

**约束**：不要在前端写入 `ADMIN_API_TOKEN`、设备令牌、Knodo PAT 或模型密钥。

### 5.2 `/learn` 学生学习首页

**目的**：学生登录后的默认首页，帮助学生立即开始学习。

**页面内容**：

- 顶部：学生头像/姓名、学段、当前设备在线状态、设置入口。
- “继续学习”：显示最近一个未结束的学习会话，点击可恢复。
- “今日学习”：课程卡片，显示课程标题、学段、描述、学习状态和开始/继续按钮。
- “学习路径”：用时间线或步骤条展示当前课程、已完成章节和下一步。
- “需要复习”：先使用练习记录或空状态；掌握度聚合接口完成前不要伪造百分比。
- 快捷入口：开始新会话、课程库、学习进度、设备中心。

**当前可接入数据**：学生列表/详情、课程列表、学习会话列表。  
**规划数据**：推荐原因、掌握度、XP/徽章、生成作品数量。

**空状态**：没有课程时显示“等待教师发布课程”；没有历史会话时显示“开始第一节课”。

### 5.3 `/learn/session/:id` 对话式学习会话

**目的**：整个产品的核心页面，持续完成“解释 -> 互动 -> 练习 -> 记录”。

**桌面布局**：三栏工作台。

```text
课程/路径        对话课堂                         教学画布
章节与今日目标    AI 消息、学生消息、引用           材料/动画/绘本/代码/练习
进度与复习提醒    文本输入、快捷问题、发送状态       预览、播放、最大化、重试
```

**功能**：

- 展示当前学生、课程、章节和会话状态：`active`、`completed`、`abandoned`。
- 加载并追加对话消息；消息角色为学生、AI、系统。
- 文本输入框、发送按钮、快捷追问；发送中显示排队/生成状态，失败时提供重试。
- 预留语音、图片输入按钮。当前没有 ASR/上传后端时，按钮显示“即将支持”或禁用状态，不要假装已成功。
- AI 消息支持普通文本、引用区域、推荐问题和教学产物入口；流式事件接入前可用明确的“演示回答”状态。
- 右侧教学画布使用标签切换：材料、动画、绘本、代码、练习。没有真实产物时显示空状态和生成入口。
- 练习区显示题目、选项/答案、提交、反馈和下一题；提交结果写入 `attempts`。
- 会话结束按钮需要二次确认，并支持完成或放弃；结束后消息输入应变为只读。
- 支持返回首页、恢复滚动位置和最大化画布。

**移动端**：不要强行压缩三栏，改为“对话 / 内容 / 路径”三个标签页。

**当前可接入 API**：创建/读取/结束学习会话、读取/写入消息、读取/写入练习记录。  
**规划 API**：流式 Agent Run、引用、Artifact、语音、图片、生成任务。

### 5.4 `/learn/progress` 学习进度和历史

**目的**：让学生知道学过什么、哪里需要复习、下一步是什么。

**功能**：

- 时间范围筛选：本周、本月、全部。
- 学习会话历史：课程、开始时间、持续状态、完成/放弃。
- 练习记录：知识点、题目、是否正确、得分、反馈。
- 课程进度：使用真实数据时展示完成章节；没有聚合接口时使用“记录已保存”而不是虚构掌握率。
- 推荐复习：先展示规则化占位，例如“根据最近一次练习推荐”；后续接入掌握度和推荐原因。
- 支持进入某一次学习会话回看消息和练习。

**状态**：加载、无记录、接口失败、记录部分缺失。

### 5.5 `/devices` OrangePi 设备中心

**目的**：查看 OrangePi 是否在线、具备什么硬件能力，并从网页安全地触发设备动作。

**设备列表**：

- 设备 ID、在线/离线、最近心跳、代理版本、平台。
- 能力标签：摄像头、显示器、音频输入、音频输出、NPU。
- 最近状态摘要：CPU、内存、磁盘、温度、播放器状态。
- 点击进入设备详情；离线设备不能发送命令。

**设备详情/控制台**：

- 硬件能力卡片和状态历史时间线。
- 命令操作：刷新状态、拍照、显示图片/视频、停止显示、播放音频、停止音频、屏幕唤醒/演示/关闭。
- 拍照成功后显示照片元数据和预览入口；照片路径只能作为受管媒体引用。
- 命令记录表：命令名、创建时间、状态 `sent/completed/failed/timed_out`、耗时、错误码、重试按钮。
- 每个危险或影响体验的动作显示确认；命令超时、设备离线、能力不支持时给出可理解的错误。

**安全边界**：页面绝不提供 SSH、远程 Shell、任意路径、任意程序或任意 URL 输入。服务端已经定义资源来源白名单和命令参数校验，前端只是调用这些能力。

**当前可接入 API**：设备列表/详情、状态历史、命令下发、命令查询、命令历史。  
**规划 API**：设备配对码、单设备凭证、共享学习会话、摄像头视觉事件和网页/机器人同步。

### 5.6 `/teacher/courses` 教师课程管理（P1）

**功能**：

- 按学段、状态和关键词筛选课程。
- 列表显示标题、学段、描述、状态 `draft/published/archived`、更新时间。
- 新建课程：标题、学段、描述、知识点 JSON/结构化表单。
- 课程详情预留单元、课时、知识点、材料和练习编辑区。
- 发布、归档操作需要确认；未实现真实权限时使用演示管理员状态。
- 显示“课程数据接口已具备，完整 CMS 尚未完成”的空状态提示。

**当前可接入**：课程创建、课程列表、课程详情。  
**规划中**：更新/删除、章节编辑、资源上传、审核、发布版本、班级分配。

## 6. 全局交互和状态要求

所有页面都必须设计以下状态，不要只生成成功态：

| 状态 | 页面表现 |
|---|---|
| loading | 骨架屏或局部加载，不跳动布局 |
| empty | 说明原因并提供下一步操作 |
| offline | 显示 API/设备离线，保留可查看的历史数据 |
| queued/running | 生成任务或设备命令显示实时状态 |
| success | 给出结果、时间和可继续操作 |
| failed | 显示稳定错误原因、重试和人工检查入口 |
| permission denied | 说明当前身份不能操作，不泄露令牌或内部堆栈 |

交互原则：

- 学生页面优先大目标、少干扰和清晰反馈；高中模式可显示更多引用、代码和变量信息。
- 保留键盘操作、字幕、朗读控制、暂停和减少动态效果等可访问能力。
- 所有按钮、数值区、棋盘、画布和状态徽标使用稳定尺寸，避免内容加载时布局跳动。
- 图标使用一致的图标库；陌生图标提供 tooltip；文本按钮只用于明确动作。
- 不用虚假的百分比、虚假的 AI 输出、虚假的设备在线状态或不可解释的“完成”动画。

## 7. 给 Stitch 的首轮生成范围

首轮只生成以下 5 个核心页面，并保证它们有统一导航、响应式布局和完整状态：

1. 登录/演示身份选择 `/login`。
2. 学生学习首页 `/learn`。
3. 对话式学习会话 `/learn/session/demo-session`。
4. 学习进度 `/learn/progress`。
5. OrangePi 设备中心 `/devices`。

课程管理 `/teacher/courses` 可以作为第 6 个页面加入，但不要在首轮生成 Provider、审计、资源解析、编程沙箱和完整内容生成 CMS，以免原型失焦。

## 9. 当前 API 对接索引

所有非健康检查和 WebSocket 接口当前使用 `Authorization: Bearer <ADMIN_API_TOKEN>`。正式前端不能直接暴露该管理令牌，后续应由身份系统和 BFF 负责授权。

| 页面 | 当前可调用接口 |
|---|---|
| 学习首页 | `GET /api/v1/students`、`GET /api/v1/courses`、`GET /api/v1/learning-sessions?student_id=...` |
| 学习会话 | `POST/GET /api/v1/learning-sessions`、`GET/POST .../{id}/messages`、`GET/POST .../{id}/attempts`、`POST .../{id}/end` |
| 学习进度 | `GET /api/v1/learning-sessions`、`GET .../{id}/messages`、`GET .../{id}/attempts` |
| 设备中心 | `GET /api/v1/devices`、`GET /api/v1/devices/{id}`、`GET .../{id}/status-history`、`GET .../{id}/commands`、`POST .../{id}/commands`、`GET /api/v1/commands/{command_id}` |
| 课程管理 | `POST/GET /api/v1/courses`、`GET /api/v1/courses/{course_id}` |
