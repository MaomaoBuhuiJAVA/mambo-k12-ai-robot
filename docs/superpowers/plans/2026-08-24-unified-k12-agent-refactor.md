# 星宝 K12 统一学习智能体重构修改计划书

版本：v1.0  
日期：2026-08-24  
适用项目：`mambo-k12-ai-robot-online-preview-source`  
依据：《附件2：第二届浙江省大学生人工智能竞赛赛题细则》

## 1. 计划结论

本次重构的目标不是继续增加多个对外可见的 Dify 应用，而是将现有能力收敛为一个对外统一的“星宝 K12 学习智能体”。绘本学习、Tip、主动提问、战斗出题、战斗反馈、初中实验辅导、高中项目答辩和学习路径建议均作为主智能体内部的工作流分支或专业能力模块。

比赛细则使用了“一个……对话智能体”的表述，但没有规定 Dify 后台只能有一个 App，也没有禁止内部拆分工作流。评分标准反而要求“智能体架构设计清晰、分工合理”。因此，统一入口加内部模块化是合规且更容易展示的方案；四个互不关联、各自暴露入口的智能体不是最终形态。

## 2. 比赛要求与重构目标

| 比赛要求 | 重构后的对应能力 | 验收证据 |
|---|---|---|
| 面向小学至高中，并按学段调整难度 | 统一上下文中的 `stage`、`grade` 和分龄提示策略 | 四个学段使用同一入口，回答风格和任务难度明显不同 |
| 对话问答 | `dialogue/storybook` 分支 | 学生可围绕当前课程和绘本提问，回答带来源 |
| 多模态教学 | 网页负责图片、绘本、动画、视频、编程环境；Dify负责解释和推荐 | 至少展示三类多模态交互 |
| 绘本生成与学习 | 版本化绘本资源 + 绘本问答工作流 | 可播放、翻页、对白、完成确认、知识点追问 |
| 游戏化练习 | `battle.question` 和 `battle.feedback` 分支 | 根据已学绘本生成题目，网站确定性判分并反馈 |
| 个性化学习路径 | 学习历史由网站保存，智能体只对候选活动进行解释和推荐 | 展示学习记录影响下一步推荐 |
| 系统部署与集成 | Next.js BFF 统一调用 Dify | 浏览器只访问 `/api/ai`，不暴露 Dify Key |

## 4. 目标架构

```text
学生浏览器
  -> 星宝网页统一入口
  -> Next.js BFF /api/ai
  -> Dify：k12-teaching-agent（唯一运行时应用）
       -> 输入校验与安全边界
       -> 学段/模式路由
            -> storybook：绘本学习与问答
            -> tip：知识点小提示
            -> proactive：主动提问
            -> battle.question：战斗题生成
            -> battle.feedback：战斗反馈
            -> lab：初中实验辅导
            -> defense：高中项目答辩
            -> recommendation：学习路径建议
       -> 分学段知识库检索
       -> DeepSeek LLM
  <- BFF 校验结果、添加来源、超时降级
  <- 网页渲染文本、绘本、动画、题目和进度
```

### 4.1 责任边界

网站负责确定性事实：绘本图片和页序、对白播放、完成状态、学习历史、题目锁定、判分、血量、战斗胜负、实验数值、课程解锁和页面跳转。

Dify 负责受控生成：适龄解释、追问、Tip、题目草案、错误反馈、学习建议和答辩问题。Dify 不得修改分数、实验指标、解锁状态、标准答案或绘本正文。

## 5. 统一 Dify Chatflow 设计

### 5.1 统一输入

主 Chatflow 的 Start 节点统一接收以下字段：

```ts
type AgentRequestV1 = {
  schemaVersion: 1;
  traceId: string;
  anonymousLearnerId: string;
  stage: "lower_primary" | "upper_primary" | "middle_school" | "high_school";
  grade: number | null;
  teachingMode: "storybook" | "dialogue" | "tip" | "proactive" | "battle" | "lab" | "defense" | "recommendation";
  battleAction?: "question" | "feedback";
  activityId: string;
  courseId: string | null;
  moduleId: string | null;
  storybookId: string | null;
  pageNumber: number | null;
  knowledgePointIds: string[];
  learningEvidence: unknown[];
  allowedActionIds: string[];
  studentInput: string;
};
```

服务端必须先验证枚举、长度和 ID 白名单，再发送给 Dify。不得发送姓名、联系方式、家庭住址、账号密码或不必要的完整未成年人聊天记录。

### 5.2 节点顺序

```text
Start
  -> Code：validate_context_and_limits
  -> If/Else：teachingMode
       storybook/dialogue -> 当前绘本检索 -> 分龄导师 LLM -> Answer
       tip                -> 当前知识点检索 -> Tip LLM -> JSON Answer
       proactive         -> 当前学习证据 -> 提问 LLM -> JSON Answer
       battle             -> If/Else battleAction
                              question -> 战斗知识检索 -> 严格 JSON 出题 -> Answer
                              feedback -> 网站判分事实 -> 反馈 LLM -> Answer
       lab                -> 实验知识/真实结果 -> 初中辅导 LLM -> Answer
       defense            -> 项目证据 -> 高中答辩 LLM -> JSON Answer
       recommendation     -> 候选活动 -> 学习建议 LLM -> JSON Answer
  -> Code：validate_output
  -> End
```

每个分支只保留一个主要 LLM 节点，避免无意义的多轮改写。战斗题、Tip、主动提问、答辩计划和推荐结果使用严格 JSON；普通讲解使用流式文本。

### 5.3 分龄策略

- 小学低年级：短句、具体角色、每次一个知识点，优先绘本、语音和简单选择题。
- 小学高年级：增加原因、比较和证据，允许一次追问和分级提示。
- 初中：围绕预测、控制变量、观察指标和因果关系组织实验辅导。
- 高中：使用代码、数据、指标、模型限制、失败案例和项目证据，鼓励独立论证。

学段由网页传入并由 BFF 校验，不能让模型根据一句学生话术自行猜测学段。

## 6. 网页侧 BFF 重构

### 6.1 统一接口

新增一个统一入口：

```text
POST /api/ai
```

前端只提交 `teachingMode`、当前活动 ID、学生输入和必要上下文。BFF 完成：

1. 用户上下文和白名单校验；
2. 拼装 `AgentRequestV1`；
3. 调用唯一 Dify API Key；
4. 将 Dify 输出按 `resultType` 转成网页协议；
5. 进行 Zod/schema 校验、超时、限流、日志和降级；
6. 隐藏 Dify URL、App ID 和 API Key。

旧的 `/api/chat` 可以先保留兼容，不在第一阶段直接替换。待统一接口通过回归测试后，再把旧入口转发到 `/api/ai`。

### 6.2 统一响应

```json
{
  "schemaVersion": 1,
  "traceId": "trace:example-001",
  "workflowVersion": "k12-teaching-agent-v1",
  "resultType": "battle_question",
  "sourceIds": ["storybook:castle-lesson-01:p04"],
  "degraded": false,
  "payload": {}
}
```

未知绘本 ID、未知动作、非法 JSON、选项数量错误、答案不唯一或来源不在白名单时，BFF 必须拒绝结果并使用本地降级内容。

## 7. 知识库重构

保留现有两套知识库，但明确职责：

| 知识库 | 用途 |
|---|---|
| 星宝 K12 绘本学习知识库 | 绘本讲解、知识点解释和对话检索 |
| 星宝 K12 绘本逐页证据库 | 战斗题、Tip、来源页和逐页引用 |

后续可按学段增加初中课程库、高中课程库和公共安全库。所有文档至少带有 `stage`、`storybookId`、`pageNumber`、`knowledgePointId`、`sourceType` 和 `contentVersion` 元数据。

绘本图片、页序和对白仍以网页版本化资源为准，Dify 只能检索清洗后的文本，不承担绘本播放器职责。

## 8. 分阶段实施计划

### 阶段 A：冻结现状与建立契约

交付：统一请求/响应类型、ID 白名单、Dify 客户端接口、Mock Provider、错误码和 trace ID。

完成标准：无 Dify Key 时本地仍可运行；非法学段、模式和活动 ID 有明确错误；现有页面不回归。

### 阶段 B：建立统一 Chatflow

交付：创建 `k12-teaching-agent`；先迁移 `battle.question` 和 `storybook/dialogue`；配置输入校验、知识检索、分龄提示和输出校验。

完成标准：同一 Dify App 能根据 `teachingMode` 路由到两条分支，战斗题返回四个唯一选项、唯一答案和来源页。

### 阶段 C：迁移战斗能力

交付：将独立战斗题逻辑迁移为 `battle.question`；增加 `battle.feedback`；网页负责锁题、判分、血量和胜负；旧战斗 App 保留为回退。

完成标准：五个战斗区域均能根据已完成绘本出题；重复渲染不会换题；Dify 超时不阻断战斗。

### 阶段 D：补齐 Tip 和主动提问

交付：`tip` 输出一个知识点、一个例子和一个可执行练习；`proactive` 根据最近学习证据提出一个适龄问题，并返回来源和下一步动作。

完成标准：Tip 不脱离当前绘本；主动问题不重复最近已答内容；低年级和高中输出深度可区分。

### 阶段 E：接入初高中能力

交付：`lab`、`defense`、`recommendation` 分支；接收网站确定性实验结果、项目证据和候选活动，不允许模型修改事实字段。

完成标准：初中回答能围绕真实指标引导验证，高中回答能要求证据并说明模型限制，推荐只来自已解锁候选活动。

### 阶段 F：统一网页入口与发布

交付：网页所有 AI 请求改走 `/api/ai`；删除前端直连 Dify 的路径；发布统一 Chatflow 和生产 Key；旧应用改为迁移回退并记录停用日期。

完成标准：比赛演示全程只展示一个“星宝 AI 学习助手”；绘本、Tip、主动提问、战斗、实验和答辩均可从同一会话或同一用户身份继续。

## 9. 测试与验收

### 功能测试

- 四个学段分别测试解释、Tip、主动提问和战斗模式。
- 七本已导入绘本逐页测试页码、对白、题目和来源。
- 五个战斗模块测试题目来源必须属于已完成绘本。
- 战斗判分、血量、解锁和完成状态只由网站决定。
- Dify 失败、超时、空结果和非法 JSON 均能回退。

### 质量指标

- 结构化输出合格率：100%。
- 来源 ID 命中当前知识库白名单：100%。
- 普通对话首段响应 P95：目标不高于 2.5 秒。
- 战斗题前台等待：不超过 15 秒，超时使用本地题库。
- 关键路径每次最多调用一个主要 LLM 节点。
- 浏览器端不出现 Dify API Key。

### 比赛演示验收链路

```text
选择学段
  -> 打开绘本并播放对白
  -> 学生提问，智能体结合当前页回答
  -> 自动出现一个学习 Tip
  -> 智能体主动提出问题
  -> 完成绘本后进入战斗
  -> 根据已学内容生成题目
  -> 网站判分并让智能体给出适龄反馈
  -> 学习记录影响下一步推荐
```

## 10. 风险与回滚

| 风险 | 处理方案 |
|---|---|
| 统一 Chatflow 尚未稳定 | 保留现有两个已发布应用作为显式回退，不影响网页基本功能 |
| Dify 网络或模型超时 | 普通对话显示本地提示；战斗使用版本化静态题库；实验使用确定性结果摘要 |
| 模型输出格式错误 | BFF schema 校验失败即丢弃，不把未经校验的字段送入页面 |
| 知识库召回错误 | 传入 `stage/module/storybook` 过滤条件，并在 BFF 做来源白名单校验 |
| 迁移期间上下文丢失 | 学习历史和当前活动由网站保存，Dify 只接收压缩后的已验证上下文 |
| 旧应用仍被误调用 | 环境变量分为统一 Key 和迁移回退 Key，发布后监控旧 Key 使用量并再停用 |

回滚只切换服务端的 Dify Provider 路由和环境变量，不回滚绘本资源、学习记录或战斗状态数据。

## 11. 需要确认的决策

1. 比赛演示阶段是否允许统一 Chatflow 使用单独的生产 API Key。
2. 是否将现有主绘本应用直接改造为统一应用，还是新建 `k12-teaching-agent` 后迁移。
3. 统一 Chatflow 发布前，旧战斗题应用保留多长时间作为回退。
4. 初高中模块接入时，是否沿用现有 TutorProtocol 和实验协议版本。

默认决策：新建或复制为 `k12-teaching-agent`，先完成 `storybook`、`battle.question` 和 `battle.feedback` 三条关键链路，验收后再切换网页；旧应用只作回退，不作为比赛主入口。
