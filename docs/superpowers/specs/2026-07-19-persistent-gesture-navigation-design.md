# 常驻手势导航设计

## 目标

开发板本机打开的网页在 `/preview`、`/robot`、实验室和学习页面之间切换时，手势识别保持运行。张开手掌移动全屏光标，握拳停住确认点击，V 手势用于上下滚动当前网页。

## 范围与约束

- 仅在开发板本机的本地代理地址启用，Windows 和其他浏览器不访问摄像头或本地手势接口。
- 复用现有的单摄像头板端视觉服务，不创建第二个摄像头进程。
- 视觉服务由根层控制；离开机器人课堂页不能停止它。
- V 手势滚动不触发鼠标点击，重新张开手掌后才允许新的握拳点击。
- 人脸识别继续共享同一摄像头，不改变其录入和匹配流程。

## 手势契约

| 手势 | 作用 | 结束条件 |
| --- | --- | --- |
| 张开手掌 | 按镜像坐标移动全屏光标 | 切换为其他手势或丢失手部 |
| 握拳并保持 1.2 秒 | 圆环进度完成后点击光标下的网页控件 | 松开拳头或完成一次点击 |
| V 手势 | 进入滚动模式，手向上移动使页面向下滚动，手向下移动使页面向上滚动 | 松开 V 手势 |

V 手势需要食指和中指伸出、无名指和小指收起。它需稳定约 200ms 才开始滚动；每次滚动使用相邻有效帧的垂直位移，设置死区和单帧最大距离，避免轻微抖动和突然跳页。滚动使用即时位移而非平滑滚动动画，降低控制滞后。

## 架构

新增客户端 `RobotGestureProvider`，由根布局在所有页面外层挂载。它是开发板本机页面唯一的手势接口消费者，负责：

1. 启动并轮询 `/_mambo/hand` 本地接口。
2. 将板端快照交给统一的手势控制器。
3. 在所有页面渲染固定的光标和确认圆环。
4. 命中网页控件时执行 DOM 点击；没有命中时保留现有板端物理鼠标回退。
5. V 手势时调用当前窗口的滚动接口。
6. 通过 React 上下文向机器人课堂页提供状态、预览和启停控制。

`RobotWorkspace` 不再拥有板端视觉服务的生命周期，也不在卸载时发送停止请求。它只消费上下文状态并显示预览、骨架和控制信息。根层卸载时才释放本地手势服务。

板端服务的 `GestureName` 增加 `v_sign`。快照保持既有 `gesture`、置信度、光标和 21 个关键点字段，因此本地代理与人脸服务无需改变通信协议结构。

## 反馈与错误处理

- 普通光标使用金色；V 手势滚动模式使用青色，以避免和点击状态混淆。
- 握拳完成后沿用绿色圆环与扩散动效。
- 手部丢失立即停止滚动、清空圆环，并要求重新张开手掌后才能点击。
- 本地接口短暂重启时，根层显示恢复状态；重新收到 `running` 快照后自动清除错误，不会因页面导航永久失效。
- 非开发板访问保持现有网页交互，不显示全局手势层，也不会请求本地接口。

## 验证

- Python 单元测试：V 手势和张开手掌、握拳、无手的分类边界。
- TypeScript 单元测试：滚动方向、死区、最大位移、从滚动模式回到点击模式的状态转换。
- 页面测试：根层在路由子页面切换时保持手势消费者；机器人课堂页卸载不再发送停止请求；非本机页面不启动服务。
- 开发板验收：从机器人课堂返回首页后仍显示光标；V 手势上下滚动首页；张开手掌与握拳仍能点击首页和课堂页按钮。
