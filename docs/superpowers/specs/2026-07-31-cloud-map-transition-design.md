# 云层地图转场设计

## 目标

当用户在首页学习旅程中选择“小学”并点击“开始”时，用参考视频中的云层切场方式进入全屏小学学习地图。动画必须由真实云图覆盖全屏，不使用白色矩形蒙版，并避免路由切换闪白。

## 范围

- 仅作用于“小学”学习入口到 `/map` 的跳转。
- 保持地图页为全屏地图体验，不添加页面导航或其他页面内容。
- 使用已有的高像素云图作为源素材；运行时由多个云实例构成，而不是放大一个低分辨率素材。
- 不改变地图热点、卡片弹层、地图返回按钮或首页的其他学习阶段逻辑。

## 架构

在应用根布局中挂载 `CloudTransitionProvider` 和固定定位的 `CloudTransitionOverlay`。Provider 不会因 `/preview` 到 `/map` 的导航而卸载，并暴露一个仅供小学入口调用的 `startMapTransition()` 方法。

Provider 拥有以下状态：

1. `idle`：覆盖层不渲染，也不拦截交互。
2. `covering`：云从屏幕外沿不规则压入，持续 550ms。
3. `holding`：云完全覆盖屏幕，导航至 `/map`，至少保持 2000ms。
4. `revealing`：地图在云后就绪后，云向外散开并降低透明度，持续 650ms。
5. `idle`：动画完成并恢复页面交互。

路由导航发生在 `covering` 完成后。地图页在地图图像及热点层准备好后通知 Provider；Provider 仅在该通知与两秒最短停留时间均完成后进入 `revealing`。为防止意外资源问题导致遮罩永久存在，Provider 还会设置一个有限的最大等待时间后自动揭示地图。

## 云层视觉与运动

覆盖层包含前、中、后三个深度层，每层放置多个不同尺寸的云实例：

- 背层：尺寸最大、透明度最低、位移最慢，提供蓝灰色体积阴影。
- 中层：承担主要遮挡，分别从左右、上下及对角边缘进入。
- 前层：尺寸最小、亮度最高、速度最快，补齐视口边缘和中部空隙。

各实例使用固定配置而不是每次随机生成，确保测试与视觉结果稳定。入口和出口不做镜像或整齐对称；云块从不同高度、不同速度进入，形成参考视频中的不规则层次。覆盖状态保持少量缓慢漂移，不使用纯白背景或全屏白色淡入。

散开阶段先让中央露出地图，再让大云向靠近的屏幕边缘撤离；小云延迟消失，最后只保留少量边缘残云后淡出。所有尺寸与位置均以视口相对值定义，确保手机、桌面和超宽窗口均能完整遮挡。

## 交互与无障碍

- `covering`、`holding` 与 `revealing` 期间覆盖层拦截指针事件，防止重复提交与点击穿透。
- 开始按钮在转场运行时呈现不可重复触发状态。
- 使用 `prefers-reduced-motion` 时跳过云的长距离位移，仅保留极短的淡入淡出并完成相同导航。
- 导航失败或地图准备信号异常时，使用最大等待超时进入揭示状态，避免不可恢复的全屏覆盖。

## 验收标准

1. 从首页选择“小学”并点击开始，云能在约 550ms 内使用真实云图完全遮挡所有视口区域。
2. 云层满屏停留不少于 2 秒；此时不会出现白色方块、底图闪烁或可点击的页面控件。
3. `/map` 已在云后显示后，云会在约 650ms 内不规则地向外散开，中央先露出地图。
4. 动画结束后地图仍保持全屏，热点、卡片弹层和返回按钮可正常使用。
5. 桌面与手机宽度下没有未被云覆盖的视口缺口。
6. 减少动态效果设置与资源准备超时均不会使用户卡在覆盖层中。

## 验证

- 为转场状态与时序添加单元测试。
- 为小学入口增加集成测试，验证调用转场而非直接路由。
- 在桌面和移动尺寸上进行浏览器截图检查，确认覆盖、停留和散开阶段的可见结果。
